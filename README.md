# 工作闹钟 · 小时

一个停在桌面角落的机器人，帮 AI 产品经理留意任务和剩余工作时间。

## 在 Mac 上演示

打开 `dist/mac-arm64/工作闹钟.app`。机器人常驻桌面，拖动改变位置，点击打开工作台。
关闭工作台不会退出桌宠。菜单栏的 `◉` 可以打开工作台、找回机器人或退出。

源码运行：安装 Node.js 后，在本目录执行 `npm ci`、`npm start`。
使用 `npm start -- --dashboard` 同时展开工作台。`npm run build:mac` 生成本机 Mac 应用。
Windows 打包入口 `npm run build:win` 已预留，但未在 Windows 上验证。

## 推荐的 3 分钟演示

1. 打开工作台，查看 09:30 的初始任务。点击“开始专注”，快进 30 分钟，看到投入时间增加。
2. 点击“模拟消息”→“新增任务”。点击“立即检查”，新任务出现在收件箱，尚未加入任务。
3. 点开消息，修改预估工时，查看“确认后的安排”，然后确认加入。
4. 暂停当前任务，点击“跳到 13:00”。查看当前容量与截止风险。此按钮在当天 13:00 之后会跳到次日 13:00。
5. 模拟“截止时间提前”，先查看变更，确认后 deadline 才会更新。
6. 模拟“等待的资料到达”，检查消息后，等待任务恢复为待开始。
7. 在“提醒与设置”点“试听并测试弹窗”。切换到其他应用，测试关键提醒是否置顶且不抢键盘焦点。

“暂停时钟”只暂停模拟时间的自动流逝；显式快进仍生效。新增的消息在下次 30 分钟检查或“立即检查”时合并接收。

## 业务规则

- 今日必须完成优先，同组按截止时间排列，可在详情中手动上移/下移。
- 当前正在做的任务优先占用预计执行时间，让临时切换造成的风险可见。
- 09:00–18:00 工作、12:00–13:00 午休、周末不排期；会议重叠只扣一次。
- 所有任务共用可用时段，同时逐项检查 deadline，不能只看全天工时总量。
- 等待资料仍保留工时与截止风险，但不会作为下一项可开始任务推荐。
- 没有 deadline 的新任务保持待确认截止状态，不能假定“今天必须完成”。
- 最晚开始前 30 分钟提醒；同一任务同一版本只触发一次。确认范围、估时或截止变化后，可产生新风险提醒。
- 计时不等于完成进度。达到预估工时且未完成，会提示补填剩余工时；不会自动勾选完成。
- 声音和语音可分别关闭。强提醒是独立窗口；新消息默认气泡加提示音。

## 数据和边界

本应用完全使用模拟邮箱、飞书联系人/群消息、日历与预设估时，不连接真实公司账户，不调用大模型。
演示从 2026-09-10 09:30 开始，所有业务共用模拟时钟。语音使用 Mac 系统 `say`，提示音使用系统声音。
数据保存在 Electron 的应用数据目录中的 `work-alarm.json`，Mac 通常为 `~/Library/Application Support/工作闹钟/`。
关闭应用和电脑睡眠不会被算作工作投入。重启任务保持暂停。电脑睡眠期间不承诺提醒；恢复后重新评估。
可在设置中重置演示，不影响任何真实邮箱或飞书数据。

本地 `.app` 未使用付费 Developer ID 签名/公证，供当前 Mac 演示使用。跨全屏/不同 Space 的配置已实现，所有组合仍需真实环境验证。

## 验证

- `npm test`：排期、截止时间、插单、等待、状态、消息确认与提醒去重测试。
- `npm run test:desktop`：独立测试存档、真实 Electron 窗口与页面操作、非抢焦点验证、重启恢复及截图。
- `artifacts/desktop-test.json`：桌面验证结果；截图在同目录。
- `REQUIREMENTS.md`：确认过的需求；`HANDOFF.md`：当前进度与未验证边界。
